# 序中盤を強化する棋譜手学習計画

決定日: 2026-09-16。状態: 計画決定、実装・学習は未着手。
本書を今後の学習方針の正本とし、[9/14計画](halfkp_training_followup_20260914.md)のH07後の分岐を置き換える。
目的は、序盤・中盤の判断を改善し、終盤の粘りを維持して、最終的にv2.5.0を上回ること。

## 1. 決定

**親の探索評価値を回帰する学習を止め、強い棋譜の実際の指し手を正解とする順位学習へ移る。**
既存HalfKPとalpha-beta探索を維持し、全合法手の静止探索末端を比較する既存MMTO実装を利用する。
新しい主目的は、棋譜手が代替手より上になるよう学ぶpairwise logistic loss（RankNet型）とする。
同一局面に複数の実着手がある場合は、その出現頻度を集約したsoft targetを使う（9/16追補、下記）。
序盤40%・中盤40%・終盤20%の局面を用い、1局面当たりの寄与を揃える。

親の役割を明確に制限する。

- scratch gen6（SHA `162e17bacea3de80ecdbbdae765ca1157246c4febb6fa6a15f8d36b900d011dc`）は初期値と比較対局相手にだけ用いる。KPP/v2.5.0由来の初期値は使わない。
- gen6の評価値・最善手を正解にせず、親出力への回帰・蒸留・anchor lossを使わない。親が棋譜手に反対しても学習対象から外さない。
- 学習中のモデルは、各合法手からどの末端に到達するかを計算するために用いる。その数値は現在の予測であり、固定教師ではない。順位の正解は常に元棋譜の指し手。
- この方式も末端選択には現在の評価関数の影響を受ける。完全にモデル非依存ではないが、弱い親の判断を正解として保存する方式とは異なる。
- 外部AIの評価値・解析PV・重み・訪問数は使わない。WDoorの実対局の盤面・指し手・結果・出典・rateは利用する。自己対局は今回の計画に含めない。

既に学んだ終盤を利用するためgen6から微調整する。今回の「教師変更」は乱数初期化へのやり直しではない。
外部AIの対局棋譜に記録された実際の着手を使うことは、ユーザーが許可している棋譜利用に該当する。

## 3. 外部調査と採否

以下は2026-09-16に一次資料を確認した。外部モデルや評価値データの導入は行っていない。

- [Hoki・Kaneko、MMTO原論文（2014）](https://www.jair.org/index.php/jair/article/download/10871/25935/):
  棋譜手と代替手の探索末端を比較し、探索と重み更新を反復して指し手選択を学ぶ。
  この枠組みを採用する。原法の最適化・正則化・反復量と本repoは同一ではなく、「原法再現」とは呼ばない。
- [平岡、Aperyの技術（2014）](https://www.jstage.jst.go.jp/article/jsoft/26/5/26_200/_pdf):
  棋譜から評価関数を学ぶ将棋の先行例として参照する。棋譜教師という方向の裏付けであって、今回のHalfKPでの性能保証ではない。
- [Burgesら、RankNet（2005）](https://www.microsoft.com/en-us/research/wp-content/uploads/2005/08/icml_ranking.pdf):
  順位確率の交差エントロピーを採用する根拠。誤った大差にも修正勾配が残る。
  論文の実験対象は将棋ではなく、MMTO末端との組合せの棋力効果は今回検証する仮説である。
- [dlshogi開発者のfloodgate教師あり実験（2021）](https://tadaoyamaoka.hatenablog.com/entry/2021/01/21/204046):
  rate・棋譜単位分割・多数局面による教師あり学習の実例。盤面・棋譜手を活用する考え方を参照する。
  大規模policy/valueネットワークや補助headを今回そのまま移植しない。
- [Stockfish NNUE資料](https://official-stockfish.github.io/docs/nnue-pytorch-wiki/docs/nnue.html#feature-factorization):
  HalfKPの疎な特徴の学習にfeature factorizationが役立つと説明されている。
  採用候補として残すが、まず教師変更を検証し、未学習特徴への誤り集中が測定された場合に限って次の変更とする。

比較した代替案: 勝敗だけの回帰は序中盤への信用割当てが粗い。独立policy headはCPU推論と探索への接続を増やす。
旧MMTOの単純増量には約10日実験の否定的証拠がある。親評価値の再生成は今回の制約に合わない。
従って、既存の探索末端・HalfKP・optimizerを生かした順位目的の変更を第一案に決定する。

## 4. 学習の具体的方法

### 目的関数と末端

棋譜手を `a*`、代替合法手を `a`、現在のモデルで求めた各手のroot手番視点の末端評価を `u(a)` とする。

```text
delta = u(a*) - u(a)
L_pair = softplus(-delta / T)
L_root = mean(L_pair over all alternative legal moves)
T = 300 cp（初期設定。勝率変換のkappaとは別物）
```

`dL_pair/ddelta = -sigmoid(-delta/T)/T`。大きく間違えた順位ではゼロに近づかない。
旧`mirrored_sigmoid`損失は正しくても誤っていても大差で勾配が小さくなる。
ただし新目的は棋譜の悪手にも強く反応するため、出典・rate選別、clip、holdout・実対局の確認が必要。
同一局面に複数の良い手があっても棋譜手一致率100%を要求しない。異なる実着手を持つ重複局面は
train内の観測頻度を尊重して扱い、splitをまたぐ同一局面は除外する。

### 同一局面の複数着手を頻度付き教師にする（9/16追補）

同一局面でAが70局、Bが30局指されていれば、Aだけを正解としてBを切り捨てず、70:30の選好として学ぶ。
これは着手の実測分布であって「Aの勝率70%」や「Aが最善である確率70%」ではない。
頻度には定跡・流行・参加プログラムの偏りもあるため、母集団は既定の高rate棋譜に限定する。
初回は勝率による再加重、年代の減衰、レート別重みなどを同時導入しない。

採用するのは既存RankNet計画のsoft target化であり、独立policy headの新設ではない。
[RankNet原論文の確率的な順位教師](https://www.microsoft.com/en-us/research/wp-content/uploads/2005/08/icml_ranking.pdf)
を利用し、着手頻度から次の教師を構成する。頻度をこの形で将棋へ適用する効果は本実験で測る。

```text
c_i = 当該局面で合法手iが指された棋譜数、N = sum(c_i)、m = 合法手数
t_ij = c_i / (c_i + c_j)
z_ij = (u(i) - u(j)) / T
w_ij = (c_i + c_j) / (N * (m - 1))
L_root = sum_{i<j, c_i+c_j>0} w_ij *
         [t_ij * softplus(-z_ij) + (1-t_ij) * softplus(z_ij)]
```

片方しか観測されていなければ通常の正例対代替手の比較となり、両方未観測のpairは作らない。
未観測手に教師上の支持がないことを、その手が悪手である証明とは扱わない。
1種類しか着手がなければ元の`L_root`へ厳密に一致する。70:30ならA対Bを70:30で学び、
50:50なら一方だけを勝者にせず同程度の評価を目標とする。pair重みの総和は1で、合法手数による寄与差を抑える。

同じ局面の異なる棋譜手を元のhard lossで頻度どおり平均しても、固定leaf上の期待損失・勾配はこの式と一致する。
したがって集約だけで新情報が増えるわけではない。明示的に集約する利点は、重複除去で少数派の手を失わないこと、
同じrootの探索を共有できること、学習順序による揺れと頻出定跡の過大な重みを制御できることにある。
少数しか観測されない中盤では単一着手の従来形に自然に戻る。実際の重複率はS01で測定する。

集約手順:

- 同一判定は正規化した盤面・持ち駒・手番の完全一致。SFENの手数欄を除き、手順前後による同一局面もまとめる。
  異なる局面が一致し得る特徴量hashだけで判定せず、左右反転・似た囲いによる追加統合は初回は行わない。
  千日手履歴が判断に影響する局面は通常群に混ぜず除外・件数記録する。
- 棋譜単位のsplitと既存holdout保護を先に行い、trainの頻度は許可されたtrain棋譜だけから数える。
  valid/test側の棋譜、着手頻度、対局openingをtrain教師へ取り込まない。共通局面の除外規則も維持する。
- 重複ファイル・転載棋譜は正規化した全着手列等で除重複し、同一棋譜・同一局面からは最大1票。
  棋譜数は統計的な完全独立性を意味しないため、プログラム名・年代の集中率も集計する。
- 集計は局面間引き前の許可済みtrain集合から行う。1棋譜最大8 rootの抽出は学習する代表rootの選択に適用し、
  選ばれたrootの頻度は全集計値を使う。頻度の集計元も学習に使った出典として記録する。
- 同一rootは1 passで1件として学習し、総出現数Nをそのままlossに掛けない。Nと着手別票数は保存する。
  異なる手数で現れるgroupのphaseは、そのsplit内の適格出現手数の中央値から一意に決める。
  unique root・元棋譜数・延べ出現数・複数着手group率をphase別に報告する。
- valid/testの分布もそれぞれのsplitだけで作る。棋譜単位の主指標集計には所属game情報を残し、
  各gameの選択rootを平均してからgame間を平均する。root単位の補助指標も別記する。

### 末端の扱い

- 全合法手を一手進めてqsearchする。parent-bestの候補選別やparent-agreement filterは使わない。
- exact leafの現在値へ微分し、leaf/root手番の符号を個別に適用する。固定qsearch値への回帰はしない。
- 詰み・千日手はルール上のterminal値として扱い、networkで無限大を近似させない。
  terminalを含むrootは第一実験の勾配対象から除外して別集計し、基本戦術の回帰評価に使う。
  これによる終盤採用率・phase比率の変化を記録する。boundや探索失敗を静的leafに偽装しない。
- 初期APIは既存の強制一手＋qsearch。通常探索を何手も追加する変更は同時に行わない。
- 1 root内のpairを上記の正規化重みで合計し、root batchで平均する。合法手数の多い局面ほど重くなる旧pair平均を避ける。
- outer全体で同一snapshotを使わず、25k rootごとに学習中重みからsnapshotを更新する。
  snapshot・optimizer・順序・root位置をcheckpointに含め、再開で対応関係を崩さない。

### データと固定条件

- まず手元の`data/wdoor/extract/2015`〜`2026`および過去に検証済みの高rate raw trainを使う。
  過去trainの再利用は可。過去valid/test/対局openingをtrainへ戻すことは禁止する。
- 初回は両対局者rate>=4000が確認できる棋譜。勝者の着手だけに限定せず、両者を使う。
  不正棋譜、合法性違反、破損を除く。結果が不明でも正規の着手列は順位学習に使え、引分に捏造しない。
- 序盤はply9〜40、中盤41〜90、終盤91以降。手数による便宜的区分と明記し、厳密な局面分類とは呼ばない。
  最初の8手は主学習から外して定跡暗記の寄与を抑え、別の補助評価へ残す。
- 1棋譜最大8 root、隣接局面の密集を避ける。序/中/終40/40/20を目標に抽出。
  受理後件数と棋譜数を記録し、不足を同じ棋譜の複製で埋めない。lossでphaseをさらに二重加重しない。
- ゲーム単位でsplitし、既存のfamily・盤面非重複検査を再利用する。validは各phase同数の計6,000 root、
  最終testも計6,000 rootを上限目標とする。独立棋譜が不足すれば件数を減らして明記する。
  過去validの再利用は開発用として明示し、新しい独立testとは呼ばない。
- 足りなければ[WDoor公式アーカイブ](https://wdoor.c.u-tokyo.ac.jp/shogi/)を年単位で追加する。
  昔の棋譜はrate欠損が多いため、年代を遡れば高品質棋譜が必ず増えるとは仮定しない。
  rate不明集合の投入は別実験とし、黙って下限を緩めない。
- AdaGradを新規に初期化し、feature LR `1e-4`、output LR `1e-5`、root batch128、clip norm1、
  output limit0.20、seed20260916、12 worker。既存material係数を固定し、推論形式・探索パラメータは維持。
  これらは初期実験の固定値で、最適値を実証したものではない。
- teacher-value loss、WDL補助loss、SWA、global decayは追加しない。終盤は棋譜手replay20%と回帰評価で保持を確認する。

## 6. 選択・対局・拡張の判断

学習とvalidはともに「全合法手のqsearch末端から棋譜手を比較する」同じ意味で評価する。
valid末端は各checkpoint自身で再探索し、併せて固定leafでの損失を補助診断に残す。
主指標は、各phase内でまず棋譜単位平均を取り、序盤・中盤を50/50で平均したlogistic loss。
top1、棋譜手平均順位、上位5手内率、誤順位側の勾配、同点率を併記し、終盤は別欄にする。
複数着手groupは、予測top1に対応する実測頻度と予測top5の実測頻度の合計も報告する。
多数派以外を選んだだけで一律不正解とはせず、単一着手groupと複数着手groupの指標を分ける。
候補は2/4/8の学習済みcheckpointから主指標最良の1個（同値なら早いもの）を選ぶ。
初期gen6との比較値は記録するが、epoch0を選んで対局が消える仕組みにはしない。

- 実装・基本戦術に重大な異常がなければ、旧value誤差の良否にかかわらず候補対gen6を50局実施する。
  両者5秒/手、同じbinary・thread条件、事前固定の互角局面25組を先後交換。これは方向を見るscreen。
- 全体得点率>50%なら独立した未使用100組・200局で確認する。採用には点推定>50%かつpaired 95%下限>50%、
  探索異常0を求める。50局だけで優位性を確定せず、不通過を同等の証明とも呼ばない。
- 初期学習前に、手元の詰み・受け・駒損回避の固定問題でgen6を測る。候補も同条件で測り、短手数の
  明確な新規失敗は原因を確認する。さらに同じ終盤開始局面25組・50局をgen6と比較し、粘りの後退を診断する。
  小規模対局で終盤の非劣化を統計的に証明したとは言わない。
- 昇格候補だけv2.5.0とtaya36・両者5秒・50局で比較する。taya36を学習・checkpoint選択には使わない。
  互角局面の結果は標準初期局面での序盤能力と別なので、事前固定の浅い開始局面でも指し手を診断する。
- 8 pass時点で4→8の序盤・中盤lossが両方改善し、終盤に明確な後退がなく、screenで50%以上なら、
  同じoptimizerから16 passまで一度だけ延長できる。追加候補の対局は未使用openingで行う。
- 確認対局で改善を支持した後、独立gameを増やして250k→1M、同じ設定8 passへ進む。既存棋譜の抽出密度を
  増やして1Mと呼ばない。1M以後の2M/4Mはその結果を見て決める。
- lossだけ改善し対局が改善しない場合は、一致率を棋力と同一視しない。誤順位の残る序中盤局面を固定し、
  qsearchだけで構想を表せないのか、未観測HalfKP特徴が多いのかを診断する。
  前者なら比較探索の通常深さ追加、後者ならfeature factorizationの一方を次の単一変更とする。
  根拠なしのLR引き上げ、同じ教師の10M化、新network・自己対局への一斉移行は行わない。

人間への棋力は内部対局だけから段級位へ換算しない。今回の成功条件は、序中盤の棋譜手判断と実対局の双方の改善である。
