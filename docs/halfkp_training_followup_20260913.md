# HalfKP 学習方針の再検討 — 2M・32 epoch後

決定日: 2026-09-13。調査対象commit: `62bfbef`。
[9/12計画](halfkp_training_followup_20260912.md)の後続方針を本書で更新する。
今回は調査と計画更新のみ。コード修正・追加学習・対局・registry変更は行っていない。

## 1. 決定

**評価記録と再開処理を最小限修正し、同じ親・教師・学習率で、新規棋譜を加えた4M局面を16 epoch学習する。**
同じ2Mを64/128 epoch反復する方法や、学習率・optimizerの一斉変更は次の本線にしない。
4Mの実験開始を旧候補の昇格に依存させる前計画を変更する。未昇格候補の採用ではなく、現行親からの別実験である。

- 初期値・教師は現行gen6（SHA `162e17bacea3de80ecdbbdae765ca1157246c4febb6fa6a15f8d36b900d011dc`）。
- 外部AIの評価値・解析PV・重み、v2.5.0/KPP由来重みは学習に使わない。WDoorから使うのは棋譜の盤面・指し手・終局結果等で、評価コメントは除外する。
- 現行scratch系統の学習成果は維持し、ランダム初期値からやり直さない。自己対局は今回も実施しない。
- gen6は既存registry上の運用baselineとして維持する。ただし後述の監査により、過去の「完全未使用集合で独立確認済み」という説明は撤回する。

## 2. 実験から分かったこと

直近run: `runs/halfkp64-scratch-v1/v4-value-gen6-2m-extended-seed20260911/`。
2,060,908件×32 epoch＝65,949,056提示。選択候補はepoch15、SHA `fc8e4ccbc187d433a6a642db2675b965ca7264e04ca6d67542e831cb23784512`。

| 観測 | 結果 | 解釈 |
|---|---|---|
| valid混合target二乗誤差 | 親0.00946764 → epoch15 0.00938164 → epoch32 0.00938648 | 今回の選択指標では15が最良。32以降の無条件延長の根拠は弱い |
| valid棋譜結果Brier | 親0.20926431 → 15で0.20792751 → 32で0.20768594 | 結果予測はその後も改善。学習全体の飽和とは言えない |
| trainの2.5乗誤差 | 15で0.00295397 → 32で0.00290764 | optimizerは更新を続けている。学習率不足を第一原因とする証拠はない |
| 開発screen、親gen6比 | 266勝225敗9分、54.1%、paired CI 49.8–58.4% | 正方向の兆候だが、既知集合上の観測 |
| 追加確認、親gen6比 | 266勝226敗8分、54.0%、paired CI 50.0–58.1%、安全違反0 | 規定の下限>50%には未達。しかも未使用集合ではなかった |
| v2.5.0比 | 今回候補は未対局。直近のgen6は5秒50局で17勝33敗 | v2.5.0超えは確認できていない |

既に参照済みtestでも親→epoch15で混合target誤差`0.00950666→0.00937528`、結果Brier`0.20938060→0.20779899`と改善した。
一方、探索値MAEは`121.04→153.93cp`。混合targetへの学習なので、探索値から離れたことだけを失敗とはしない。
phase別では終盤の改善が中心で、序中盤の混合target誤差は親より悪化している。全体平均だけで判断しない。

**進展はあるが、大幅な棋力向上を示した段階ではない。** 正しい価値学習・教師更新には過去の親超え観測がある一方、旧rank符号・尺度・教師形式に問題のあった実験を、現在の学習方式の限界を示す証拠にはしない。
trainは2.5乗、validの選択値は2乗なので、両者の数値を直接比較して過学習と断定することも避ける。次回は同一損失のtrain/valid診断を併記する。

### 今回見つかった記録・実行制御上の不備

1. **確認局面の再利用。** 今回のreserve 1001–1250は、過去4 runで全250 family・record SHAが使用済みだった。
   既存final 2,000局面集には、ローカルの対局履歴で未使用のfamilyが0件。
   gen6対gen5の確認250局面も8/24のrunで全件使用済みだった。勝敗は消さないが、完全未使用の確認結果として扱わない。
   再利用が勝敗をどれだけ偏らせたかは未測定であり、全結果が無意味だったとも言えない。
2. **bestの指標が再開時に混在。** manifestのselected epoch/scoreは15だが、`selected_validation`詳細は28相当。
   再開時にcurrentの評価をselected詳細へ代入し、best更新がなければそのまま残る実装が原因。
   対局したモデルSHAはepoch15と一致しており、勝敗自体は無効にならない。
   また`model-epoch-N.bin`は各時点のbestで、N時点のcurrentではない。bestとcurrentの区別・best SHAの再開検証が必要。
3. **後続watcherの完了判定。** v2.5.0 watcherは確認対局前の中間`gate-decision.json`のfalseでも終了し、非空の`match.log`を完了扱いする。
   今回の最終skip結論は変わらないが、次回の自動進行前に修正する。

これは学習勾配に新たな致命的バグが確定したという意味ではない。元reportやmanifestは上書きせず、
[今回の監査記録](../training/halfkp64-scratch-v1/followup_review_20260913.json)にSHA・重複run・不整合を残す。
計画逸脱について指定どおりGPT-5.6 Sol・Maxへ助言を求め、最小修正後の4M実験という優先順位を再確認した。

## 3. 次の学習方法

### データ: 反復を新しい棋譜由来の局面へ置き換える

- 既存の重複除去済み2,060,908件を保持し、新規1,939,092件を追加して、最終的な学習入力を4,000,000件にする。
  数えるのは抽出前のroot数ではなく、教師生成・不正除外・同一network入力重複除去後のHKST件数。
- まずローカルWDoorに残る未採用gameを使い、不足時だけ古い年のarchiveを追加取得する。現在2015–2026年のarchiveがある。
  年が違うだけで独立とは扱わず、既存scratch系統の使用game、valid/test、確認対局用game/familyを除外する。
- 新規抽出は従来同様、1 game最大24局面、序中終盤各最大8、ply 8–200、終局結果既知。rate閾値やphase重みは同時変更しない。
  重複後の件数が不足したら追加gameで補い、同じgameからの抽出密度を増やして4Mを満たさない。
- 新規game数、年・phase・rate既知/欠損の内訳、除外率を記録する。新旧を混ぜてから、seed固定の局面shuffle/shard化を行う。
  train/valid/test分離はgame単位を維持し、qsearch leafのnetwork入力も交差確認する。既存validは開発用のまま固定する。
- 教師はgen6、100k nodes、depth上限8、現行の`deep-search-target-v1`＋qsearch leafを維持。
  qsearchの値を教師へ置き換えず、完了した通常探索のroot値と手番反転を保持する。完了depth分布・失敗率も記録する。

### 学習: 4M×16 epoch、他条件固定

| 項目 | 設定 |
|---|---|
| init / optimizer | gen6から開始、AdaGrad。optimizer初期化はrun開始時だけ |
| feature / output LR | 3e-4 / 3e-5 |
| target | 自作探索80%＋棋譜結果20%、kappa 1352.7871 |
| loss / batch | power2.5、batch128、rank全て0 |
| その他 | clip1、output-limit0.20、SWA無効、12 worker、seed20260911 |
| 学習量 | 4/8/12/16 epochで保存、上限16。64M提示 |
| 選択 | 初期親を含むvalid混合target二乗誤差の厳密best、同値は早いepoch。結果Brier/log-loss・phase・同一2.5乗損失を補助診断 |

直近2.06M×32の65.95M提示と概ね揃えることで、同じ局面の反復と新規gameの追加を比較する。
順序・最良epoch・分布は変わるため厳密な単一因子の無作為試験ではないが、LR・教師・目的まで一斉変更するより原因を追いやすい。
親改善がまだ未確認のepoch15/32を初期値・教師にはしない。
微小な横ばいでは16以前に止めない。非有限値・artifact不整合は停止し、前計画の持続悪化規則は維持する。
16以降は自動延長せず、この実験の候補を1個凍結して評価する。

### 評価: データ拡張の効果と親昇格を分ける

1. 重み更新なしで親・既存2M best・4M候補を同じvalidで比較する。既知testを再参照しても、選定には使わない。
2. 開発screenは既知250 pairで、**4M候補対既存2M best（epoch15）**を実施。安全違反0・得点率52.5%以上なら次へ。
   これはデータ拡張の開発上の確認であり、独立した有意差の証明ではない。
3. 昇格確認は**4M候補対運用親gen6**を、新しい250 pairで一度だけ行う。
   過去全runと学習由来のgame/family、同一盤面、record SHAを照合し、新規集合を学習前に凍結する。
   `opening_family`の文字列が違っても同じ棋譜/盤面を別物として通さない。不明な由来は確認用に採用しない。
4. 各20k nodes/手、先後交換、最大500局ずつ。paired bootstrap 100,000回、seed・モデルSHA・条件を事前固定。
   確認の得点率52.5%以上・95%下限>50%・安全違反0でのみ昇格。途中結果で延長・差替え・再抽選しない。
5. 昇格時にtaya36・両者5秒・50局でv2.5.0と比較する。50局の僅差だけで大幅超えやreleaseを断定しない。

250 pairは小幅改善を取りこぼし得る。大量対局を避ける方針を維持する代わりに、未達は「改善なし」ではなく「優位性未確認」と記録する。
旧epoch15を新局面で合格するまで再試験することはしない。新候補の試験から評価の独立性を回復する。

## 4. 4Mの後に何を変えるか

- **2M比の開発改善と親比の新規確認が成立:** 新accepted親で教師を更新し、8M〜10Mへ段階拡張する計画を立てる。今回から自動で10Mへ進めない。
- **4Mでもofflineだけ、または序中盤の悪化が続く:** 新しい巨大データ作成を止め、固定・phase層化5k rootで同じgen6の100k/depth8対300k/depth12を診断する。
  共通rootの完了depth、結果較正、root/leaf整合、生成時間を比べる。過去5kでは100kの完了depthは主に3–4で、上限8と実深さは異なる。
  深くする有益性は未確認なので、差が有望なら同一root集合の小規模学習A/Bを経て本生成へ進む。棋譜結果Brierだけで教師の優劣を断定しない。
- **同じ目的のtrain/validも止まり、実効更新が極小と分かった場合のみ:** 同じ初期値・データ・提示数でLRの単一比較を行う。
  目的の偏りが主因ならmixまたはphase抽出の一つだけを変更する。今回の結果を見て複数を同時に変えない。

MMTO-only再開、巨大network、新optimizer、自己対局基盤の新設は今の優先作業ではない。
長時間学習が役立つのは有用な教師・多様な入力・正しい更新と評価が揃う場合であり、「優れたalgorithmで長く回せば必ず超える」とは保証できない。
